    Part 2: Bounding Volume Hierarchy

    BVH Construction Algorithm

    In BVHAccel::construct_bvh, we use a recursive approach to build the bounding volume hierarchy. We first iterate from start to end to compute a bounding box (BBox) that includes all primitives in the current node. We then check the leaf node case: if the total number of primitives is less than or equal to max_leaf_size, we create a leaf node, assign the start and end iterators to it, and return the node.

    If the node contains more primitives than max_leaf_size, we must split it to create an internal node. For our splitting heuristic, we use the average centroid along the longest axis. We first compute a centroid_bbox that bounds the centroids of all current primitives. We evaluate the extents of this centroid_bbox in the \(x\), \(y\), and \(z\) dimensions and select the longest one as our splitting axis.

    Then, we calculate the splitting point by averaging the centroid positions of all primitives along this chosen axis.

    Next, we use std::partition to divide the primitives based on the split point. Primitives with a centroid coordinate less than the split point are partitioned to the left side, and the rest to the right. To prevent infinite recursion in edge cases where all primitives cluster on one side (i.e., mid == start or mid == end), we explicitly force the array to split in the middle: mid = start + count / 2.

    Finally, we recursively call construct_bvh to build the left (node->l) and right (node->r) child nodes.

    Performance Analysis

    Implementing BVH acceleration provides massive performance improvements. Without a BVH tree, the ray tracer tests every ray against every primitive, resulting in \(O(N)\) time complexity per ray. By organizing primitives into a BVH tree, we reduce the intersection testing time complexity to roughly \(O(\log N)\).

    Scene Name Render Time (No BVH) Render Time (With BVH)
    cow 6.3221s 0.0362s
    coil 7.9054s 0.0265s
    bunny 49.7231s 0.0266s
    dragon 165.0446s 0.0305s

    As shown, scenes like the dragon that took over two minutes to render natively now complete in fractions of a second. This logarithmic efficiency becomes absolutely essential for rendering large models.
