    Task 1: Drawing Single-Color Triangles

    Triangle Rasterization Algorithm

    To rasterize triangles, I implemented a bounding box approach. First, I determine the bounding box of the triangle by finding the minimum and maximum x and y coordinates of the three vertices, clamping them to the screen resolutions. I then iterate through every pixel coordinate \((x, y)\) within this bounding box.

    For each pixel, I calculate the center point \((x + 0.5, y + 0.5)\) and perform a point-in-triangle test. This is done using the three test functions derived from the cross-product of the triangle's edges. If the point lies on the correct side of all three half-planes (either all positive or all negative, depending on the winding order), the pixel is considered inside the triangle and is colored using fill_pixel.

    \[ L_i = (P_{i+1}-P_i)\times (x-x_i,y-y_i) \]

    Efficiency Check

    My algorithm is no worse than one that checks each sample within the bounding box because it does exactly that: it restricts the search space to the rectangle defined by \([min\_x, max\_x] \times [min\_y, max\_y]\). It never checks pixels outside this range, ensuring the complexity is proportional to the area of the bounding box rather than the entire framebuffer.

    Extra Credit: Optimizations

    I implemented two optimizations to improve rasterization speed beyond the simple bounding box check.

    1. Incremental Test Function \(L\) Updates: Instead of computing the full test function \(L_i(x,y)=-(x-X_i)dY_i+(y-Y_i)dX_i\) for every pixel, I calculate an initial value at the start of the loop. For each step in the inner loop (as x increases), I simply update \(L\) by adding \(-dY\). When moving to the next row (as y increases), I add \(dX\). This avoids performing time-consuming multiplication operations for every single pixel.
    2. Early Exit: Since a triangle is a convex shape, if we are iterating along a line and have already entered the triangle, the moment we step outside the triangle, we know we will not re-enter it on that same line. I added a flag entered; if a pixel fails the edge check and entered is true, I immediately break the inner loop.

    Performance Comparison

    I tested these changes using test3.svg. The Early Exit provided the biggest speed boost.

    Version Average Time (ms) Speedup
    Baseline (Naive Bounding Box) 10.341 1.0x
    Optimization 1 (Incremental Updates) 9.427 ~1.10x
    Optimization 2 (Early Exit) 6.870 ~1.51x
